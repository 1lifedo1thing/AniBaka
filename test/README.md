# 测试

在项目根目录运行：

```sh
fvm flutter test --no-pub
fvm flutter analyze --no-pub
```

## 结构和保障范围

- `core/`：账号隔离、请求去重、存储恢复、匹配排序、规则解析与解码、HLS 安全过滤。
- `services/`：收藏同步、历史恢复、规则索引缓存、凭证并发、媒体探测、种子解析、日志下载访问限制。
- `features/`：播放控制与配置迁移、选集换源、一起看同步、弹幕、拖动进度与播放页状态保留。
- `support/`：按需装配源或播放依赖，共用真实 TS 分片前缀；规则仓库由使用它的测试创建。

目前没有 `integration_test/` 或 Golden 测试。`.github/scripts/tests/` 中的发布签名测试
保护签名验证与打包顺序，单独保留，不纳入 Flutter 测试耗时。

## 维护约定

长期保留能保护核心流程或高损失故障的测试：账号与凭证隔离、存储恢复、收藏和历史、
规则解析与回退、播放和下载生命周期、取消及过期结果隔离。测试只涉及某个功能，
并不等于没有价值；判断标准是它能否发现仍可能发生的真实错误。

不保留一次性重构的旧算法对照、大规模随机等价循环、仅证明优化实现的对象复用或
分配次数断言、配置常量快照，以及字体预览、封面或 Logo 选择等展示细节的专用测试。
临时排查用的脚本、替身和样例应随排查结束一起清理。同一行为已由完整流程验证时，
删除重复的辅助函数测试；有持续价值的回归场景并入对应模块，不另建一次性回归文件。

按模块添加有风险的行为场景，优先放入已有文件。验证输入、结果、状态变化和持久化结果，
不为类、字段或静态 UI 单独建测试。原生播放器、HTTP 和字体资源边界可以使用小型替身；
纯解析与配置测试无需初始化完整应用服务。

异步测试等待 Future、请求到达或状态通知，不用固定毫秒数猜测任务何时完成。
请求调度与流释放统一放在 `request_scheduler_test.dart`；流结束、取消和错误由可控流触发，
HTTP 取消仍经过真实本地服务器。播放同步使用 `pump` 排空微任务，
`pumpAndSettle` 用于仍需完成的导航、滚动和弹窗动画。超时与保活测试保留业务时间边界，
不能省略后直接断言超时或停止；这些场景不作为性能指标。
